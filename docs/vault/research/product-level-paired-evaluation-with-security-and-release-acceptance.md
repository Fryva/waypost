# Product-level paired evaluation with security and release acceptance

## Result and equal readiness

Both final Local Notes1.0 packages were completed and accepted to the same registered product requirements:92/92external HTTP/security/persistence/concurrency/CLI checks, meaningful own npm test, the supplemental chronological-date regression,9strict token/UUID boundary controls and all12registered real-browser journeys. Browser evidence includes actual failed filesystem writes with retained drafts and successful retry, backup restoration, destructive-action cancellation, literal malicious titles, reload access and360px/desktop layouts without horizontal overflow. A fresh origin-blinded assessor inspected all eight files of both products plus source-bound receipts and returned pass/pass, equivalent required quality, no findings. Finite tests/source review do not prove absence of all vulnerabilities.

W-v1 and N-v1 passed the original corrected92-case corpus but both sorted canonical expanded-year ISO timestamps lexicographically. W independent review identified the defect; a real HTTP import/list regression reproduced it. Each original author then repaired its own product in the same native context and added regression tests. Both final products passed again. N received only its actual failing assertion, not the W source, plan or reviewer hints. No unfinished version is used as the baseline; every failed version and correction is retained and counted.

## What this establishes

The additional W review found and drove correction of a real contract defect missed by the initial tests; both initial implementations contained it. Required final quality was achieved in both products. This run supports the usefulness of that independent review, but did not show net token savings or a superior accepted final required quality for W. It is one small complete local product, not a large distributed/security-critical product or statistical estimate. No positive economic result was assumed or selected.

The protocol is a compliance-checked packet simulation with a common native harness: N omits explicit Waypost roles/story/plan/commands, not every ambient Waypost instruction or tool-catalogue token. It does not exercise autonomous repository navigation or enforce OS source isolation. W-first order and cache effects prevent billing/uncached causal claims. The date regression was derived from W review and then applied equally to N, coupling acceptance evidence between arms. Delivery amendments, unequal read counts and failed deliveries further limit attribution. Full native input+output is counted; cached/reasoning tokens are subsets. No conversion to money or weekly subscription quota is justified.
