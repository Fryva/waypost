# Paired implementation simulation with equal acceptance

## Preregistration

Owner request 2026-10-22 explicitly authorizes two executions with/without Waypost and equal quality. This new experiment is not N1/A1, C1-C3, the failed CLI broker pilot, a protected team role or permission to change old ledgers. Old frozen protocols/allowance/receipts remain unchanged. Read-only packet-mode outputs are implementations as text; the operator alone applies them in disposable test directories. This changes tool/navigation scope explicitly under ADR option4, not claims that earlier runtime gates passed.

One handcrafted task: dependency-aware deterministic batch scheduling. Source/task bytes are identical. Conditions: W uses canonical Waypost planning and review prompts plus story/lifecycle/task packet; N uses ordinary direct implementation and self-checking. Same native default Codex model/effort for all measured calls, not model overrides. Every measured context is fresh (fork_turns none). Each context is allowed exactly one initial read of its assigned packet through exec_command/cat; all other tool use is forbidden and invalidates the condition. Native traces must confirm only that exact read. This common bootstrap incurs real counted input/output in both arms. This is a compliance-checked packet simulation, NOT technical no-tools/source isolation or a navigation benchmark. Common native harness/global instructions may still contain Waypost references: this measures explicit workflow delta, not the removal of every standing Waypost token. Do not claim otherwise.

Order: W planner -> W author -> W independent reviewer -> W fixes if needed; then N author -> N fixes if needed. Equal acceptance is imposed by the same frozen hidden deterministic test corpus and an origin-blinded joint code review. One shared judge evaluates masked plain source against one rubric, without arm labels or token counts. Shared judge cost is excluded from the paired difference and separately reported. W's required planner/reviewer cost is included in W. Do not count useful work as wasted: W-N is incremental workflow cost for equal accepted outputs, not all W usage as overhead. Controller artifact/protocol creation and driving/reporting are separately measured where native counters permit; unclosed tail remains unknown, not zero.

All failures and revisions count to the originating arm; repairs continue in the same author context until common final acceptance, as explicitly clarified by the owner. Each correction, prompt, revised response and required W rereview is charged to its arm. Any unresolved quality issue makes the pair inconclusive, never relax tests or choose a more favorable retry. Record first-pass TEST acceptance and final full acceptance. No automatic repetition, model search, warmup or calibration; no output-token-only totals. All native input/cached/output/reasoning counters and identities retained. Sum unique owned token_usage_record usage from creation through final response; cross-check each native cumulative delta and final cumulative. First record must equal its owned initial cumulative, otherwise full usage unknown. Never use a copied parent prefix/foreign frame or assumed zero. Missing/partial/drifting/foreign identity or tool violation invalidates cost/condition and stops subsequent measured calls.

All measured calls use inherited default settings. Verify actual turn_context model/effort in native logs; if model/effort differ, no pure workflow attribution. No provider-dollar/weekly-quota conversion. Planned invocation ceiling: one planner, one W author, one W reviewer, one N author, one shared judge plus all necessary repairs/rereviews and repeated blinded acceptance after fixes; no favorable-retry selection. Native invocation totals checked after each call; stop future calls if measured stages exceed232480tokens (conservative remaining amount from historical250000minus17520, independent observation only, not a second authority ledger or guaranteed provider cap). Setup/driving costs are outside this comparison cap, separately disclosed. No old budget mutation; no new CLI controlled inference.

Quality rubric, identical: fixed tests all pass; graph algorithm follows stated batch semantics; validation/errors complete; deterministic and input immutable; plain maintainable dependency-free implementation with no material review findings. Blind judge may return pass/fail per source and concrete material findings; test results have priority over subjective approval. A single pair is a task-specific smoke, not a statistical causal estimate of all Waypost usefulness.

Pre-register task, tests, reviewer prompts and protocol hashes before measured author/planner calls. Protocol gets a fresh independent critic before launch; include critic/authoring overhead outside arms. Worktrees and durable source-code production edits are not needed; retained accepted source and test hashes allow reproduction. Temporary test directories removed; private receipts/outputs/runners retained. Publication contains aggregate/source identities, not private transcript bodies.


## Frozen repair and bootstrap policy, before measured dispatch

Run hidden tests immediately after every submitted implementation, before W's internal reviewer or the final blind judge. If tests fail, the author receives only unchanged common task, its own latest source and the machine-generated failed test name plus assertion error/stack; never the full test source, opposite output, reference implementation or operator algorithm hints. Same format for W and N. W internal reviewer findings are permitted additional W assistance and counted there. Repairs use the original author context; rerun the exact frozen corpus after each revision. Failure exhaustion is not acceptance. The owner explicitly requires N to reach the same final result: the earlier two-repair ceiling is superseded by that clarification. The native comparison threshold is an operational admission forecast, not a new authority budget; if it prevents equal completion the comparison remains incomplete, never claim savings.

A single final origin-blinded joint judge is common experimental assessment, separately reported, not a free hidden helper in either workflow. If it finds a material issue, send only the finding for that author's own source, count repair prompts/responses to that arm, then repeat blinded assessment for both retained sources. Count all such assessment calls in the common assessment total and disclose them. Present W, N, shared assessment, measured setup/driving, and their sum separately so no correction or review disappears. Also show symmetric half-assessment allocation for end-to-end comparison; this is an explicit cost allocation, not separate native per-arm metering. No complete first-pass quality claim unless judged; only first-pass test acceptance.

The loader message permits one tool read of one assigned immutable packet and final output only. The packet contains task/source plus canonical role prompt for W planning/review. A repair context may read only its new assigned feedback packet. No directory browsing, project initialization, hidden tests/reference/opposite output, network or other tools. This is verified tool compliance, not OS isolation. Default author/planner/reviewer/judge all use the inherited native configuration; role bodies are prompts rather than model-setting overrides. Verify equality from native turn_context records. Freeze exact packet hashes before each dispatch.

## Scope and interpretation

This is one handcrafted scheduling module, not a finished product. It tests
functional correctness/maintainability under packet-mode; it does not exercise
autonomous navigation, UI, deployment, real adversarial product threats or
long-term correction/maintenance. Common Codex ambient instructions/tool
catalogues remain in both arms; N omits explicit Waypost roles, plan, story and
commands, not every possible background mention. The common machine resource
gate runs outside both model workflows. Default inherited medium effort is held
constant; canonical role bodies do not switch to their normal max-effort setting.
Fixed W-first order and cache warmup prevent interpreting uncached-token/dollar
differences as pure workflow effects. One pair gives no statistical estimate.

The owner subsequently requested full product/security/release evaluation. That
is a separately frozen experiment, not a replacement of this unfavorable result.
Neither this result nor the next protocol assumes Waypost must save tokens.
